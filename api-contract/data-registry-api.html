RHOAI Data Registry API (0.10.0)

Download OpenAPI specification:

License: Apache-2.0

The RHOAI Data Registry exposes an Iceberg REST-shaped API for registering, discovering, and managing data assets across OpenShift AI projects.

This contract covers bootstrap configuration, namespaces, table listing, table metadata retrieval, and existence checks. Declared write operations have limited support; for example, updateTable documents only property actions. Do not assume every operation required by an Iceberg client works.

The API uses a three-level namespace model:

/v1/{project}/namespaces/{collection}/tables/{table}
     ^^^^^^^^            ^^^^^^^^^^^^        ^^^^^^^^
     RHOAI Project       Collection          Asset name
     (K8s namespace)     (logical group)

API Surfaces

The Data Registry exposes two complementary API surfaces on the same server:

  1. Iceberg REST-shaped — Catalog discovery and metadata operations with limited write support; this is not a claim of full client compatibility.
  2. RHOAI Extensions — Additive endpoints for volume management, multi-format asset registration, connection-based asset lookup, and search. These do not break spec clients.

Authentication

All endpoints require a Bearer token (Authorization: Bearer <token>). A kube-rbac-proxy sidecar authenticates via Kubernetes TokenReview and authorizes via SubjectAccessReview (SAR) for project-prefixed routes. The unprefixed /v1/config bootstrap route has no project in its path; its authorization behavior must be verified for each supported deployment, including calls without the optional warehouse parameter.

Authorization

Registry requests are authorized against the OpenShift project in the URL. The feast-data-registry-viewer and feast-data-registry-admin ClusterRoles can be bound in a project for read and manage access, respectively. Dashboard project discovery uses separate OpenShift project permissions.

Error Responses

Error response bodies use a consistent Iceberg REST format (except HEAD, which has no response body): {"error": {"message": "...", "type": "...", "code": N}}

search

Full-text search with relevance scoring (RHOAI extension)

Search data assets within a project

Search registered tables, volumes, and collections inside the Kubernetes project named by {project}. Path {project} is an exact, case-sensitive Kubernetes namespace (SavedDataset.namespace).

Query text (query). Case-insensitive. Empty or omitted includes every in-scope asset that passes filters, each with score 0.

Scoring (first matching bucket wins; integer scores only):

  • 100 — exact match on name
  • 90 — name contains the query
  • 80 — description contains the query
  • 60 — a searchable value contains the query: first-class metadata (description is scored at 80; otherwise owner, format, labels, collection properties, user properties values — not keys), schema column name / type / description, or storage_location URI
  • 40 — fuzzy name match (Jaccard ≥ 0.75, query length ≥ 3)

Non-matching rows are omitted. Hits are slim: type, namespace (one-element collection array), name, description, properties, score. Clients that need format, owner, labels, or storage should GET the asset.

Type filter (asset_type only). There is no type query parameter. Case-insensitive. Aliases: dataset → tables; iceberg_table → tables whose format is iceberg. Unknown asset_type values produce no hits: page 1 returns HTTP 200 with results: [], while page greater than 1 returns HTTP 400 because there are no results to paginate. Result type is only table, volume, or collection.

Collection filter. namespace and namespaces are aliases for SavedDataset collection. Case-insensitive exact match. Omitted or empty means all collections, including the implicit default collection. When a collection filter is set, collection rows are omitted from results.

Label filter. Single label query parameter: case-insensitive substring on asset labels. Collection rows are omitted when label is set. This is not generic-table GET .../generic-tables?label= (exact membership).

Property filter. Repeat properties=key:value. AND across pairs. Case-insensitive substring on values. Missing :, empty key, or empty value → 400. A colon inside the key (properties.a:b=x) is 400.

Pagination / sort. page (1-based, default 1). limit (default 50, max 500). page_size is an alias of limit; when both are sent, page_size wins after both supplied values pass validation. For example, page_size=25&limit=501 returns 400 even though page_size takes precedence for valid values. sort_by is score (default) or name. sort_order is asc or desc; when omitted, desc for score and asc for name. Name sort is case-insensitive.

Pagination object. Nested Feast paginate_and_sort shape: page, limit, and when there is at least one hit totalCount / totalPages. hasNext / hasPrevious appear only when true. Zero hits omit totalCount (and typically totalPages). page below 1, page past totalPages when hits exist, or page>1 when there are zero hits → 400. limit / page_size above 500 → 400.

Errors. Validation failures use Iceberg ErrorResponse {error: {message, type, code}}.
